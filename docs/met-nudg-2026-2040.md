# MET + nudged runs 2026–2040: workflow record

**Decided:** user, 11 Nov 2026. **Plan approved:** 15 Nov 2026 (`~/.claude/plans/7-met-and-nudged-tidy-volcano.md`). **Built and started by:** session fc06b4b6.

**Goal:** extend all 12 new-chain nudged runs from 2026-01-01 to 2041-01-01, then postprocess 2001–2040 and rerun the analysis, fully automatically. The MET run, which supplies the nudging data, goes first.

## Logic

1. **MET runs first.** MET is the free run whose 6-hourly winds, temperature and pressure nudge every other run. It is continued **in its existing case**, with no new case: three 6-yr jobs, 2026→2032→2038→2041-01-02.
   - The last job is cut by `STOP_DATE`.
   - MET stops 1 day past 2041 so the met data have a record after the nudged runs' last time step.
   - The jobs are 6 yr, not 5, because `STOP_DATE` only shortens a job: 3 × 5 yr would end at 2041-01-01. The 2015–2025 job (12d) used the same trick.
2. **After each MET job is archived**, its new days become calendar-day nudging files in the one folder `…_6h_2000-2040`, and the new list grows.
3. **A nudged run only simulates years whose met files exist.** Each run goes in three 5-yr phases:
   - A: 2026→2031
   - B: 2031→2036
   - C: 2036→2041

   A phase starts when the list reaches its end day and that run's previous phase is archived. The 12 runs move independently of each other.
4. **Gate:** after MET job 1, the new h1 `2026-01-01-21600` must equal the original one, value for value. If it doesn't, everything stops before any nudged run moves.
5. **When a run reaches 2041-01-01:**
   1. it is copied to NIRD;
   2. it is postprocessed for 2001–2040 (12 spin-up months dropped), in 2 queues of 6 runs (one retry of failed jobs).
6. **When all 12 runs are processed:**
   1. the 2001–2025 figures and tables are kept as copies;
   2. the analysis switches to 2001–2040 and reruns the 9 notebooks.

## Nudging data: one folder `…_6h_2000-2040`
CAM never reads the folder itself. It reads one list file of full paths (`met_filenames_list`). At a restart it looks up the exact path stored in the restart (`current/next_metdata_filename`).

**Why regroup:** MET's h1 files run from 06 h to 00 h of the next day. The nudging wants one file per calendar day with 00/06/12/18 h, so each day is built from two MET files (`regroup_met_ext_days.py`), with every record verified bit-identical to its source.
